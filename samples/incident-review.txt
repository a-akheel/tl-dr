The service experienced elevated error rates during a database migration on Tuesday morning. The migration changed an index used by the customer search endpoint. Requests to customer search became slower and occupied application workers for longer than expected. Monitoring detected the error increase and alerted the on-call engineer. The engineer rolled back the migration and verified that search requests returned successfully. Other endpoints remained available throughout the incident. The team will add a representative search workload to the migration test suite. Future migrations will first run against a staging database with production-like record counts. The release owner will document a rollback plan before approving the next migration. Customers received an incident update explaining the affected endpoint and the recovery action.
